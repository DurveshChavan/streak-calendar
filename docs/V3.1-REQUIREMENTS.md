## 2. Habit kinds

| ID | Requirement |
|---|---|
| R-K1 | Kinds: **Build daily**, **Build weekly**, **Reduce**, **Number**. |
| R-K2 | **Build daily** is due every day. There is no "days per week" setting. A user who wants fewer days uses Build weekly. |
| R-K3 | **Build weekly** has a goal N per week. The user ticks the days it happens. |
| R-K4 | **Reduce**: the main number is **resisted urges**. A weekly budget is optional. If a budget is set, the app logs the count of times it happened and shows "x of N used". If no budget is set, the app does not log a count. (D3) |
| R-K5 | **Number**: one value per day, with an optional weekly target. (D2) |
| R-K6 | **Avoid** is a separate list, not a habit kind. Each item has a name and a replacement action. Nothing is logged, ticked or scored. The list is a section of the habits sheet. (D2) |
| R-K7 | A 2.0 habit is a Build daily habit with no other change. |
| R-K8 | A habit can be paused (moved to Later). It keeps its data, shows no ticks, and does not count in scores or streaks. Later is a section of the habits sheet. |

## 3. The day

| ID | Requirement |
|---|---|
| R-D1 | A build day has three states, as in 2.0: done (`t`), missed (`x`), blank. **Only `x` is a miss.** A blank day is unknown: it is not a miss, it does not break a streak and it does not start a miss rule. |
| R-D2 | The day note stays as in 2.0: one free text per day, shared by all habits. |
| R-D3 | Each habit has its own **reason** per day. The reason field shows only when a Build habit is marked missed (`x`). It is optional. (D4) |
| R-D4 | Daily score "x / N": N = active Build daily habits. x = how many of them are done. Build weekly, Reduce and Number are **not** in the score. A day with nothing done shows grey "0 / N". (D13) |

## 4. Progress

| ID | Requirement |
|---|---|
| R-P1 | Main badge: **total** is the biggest number, streak is smaller. (D6) |
| R-P2 | Total per kind: Build = all done days; Reduce = all resisted urges; Number = sum of values. A total never goes down (except when the user removes a mark). |
| R-P3 | "This week" against goal or budget, for example "2 / 3", "4 of 10 used". |
| R-P4 | Trend: 8 weekly bars, on the habit detail screen. (D5) |
| R-P5 | Streaks: Build daily = consecutive done days, broken only by `x` (2.0 rule, unchanged). Build weekly = consecutive weeks with the goal met. Reduce = consecutive weeks within budget (only if a budget is set). Number = no streak. The current week never breaks a week streak until it ends. |

## 5. Colour of a miss

| ID | Requirement |
|---|---|
| R-C1 | A missed day is grey. No red on a miss. (D1) |
| R-C2 | Red stays in the palette as an accent only. Red is never used for a miss or any negative state. (D12) |
| R-C3 | Palette choice (new skill default or current app palette) is made in phase 2, with both shown. (D11) |

## 6. Timers

| ID | Requirement |
|---|---|
| R-T1 | Build: "just start", default 5 min. At the end, the day is marked done. Reduce: "delay", default 20 min. At the end, one resisted urge is added. The replacement action shows while the reduce timer runs. Length is editable per habit. |
| R-T2 | Stop early: nothing is counted. No penalty. (D7) |
| R-T3 | Only **one** timer runs at a time. Starting a new timer asks to cancel the current one. |
| R-T4 | The timer survives a locked screen through a native Android notification. |
| R-T5 | If notification permission is denied: the timer still runs in the app. The app stores the end time. When the app opens after the end time, the result is counted. The app shows a hint to turn on notifications. |
| R-T6 | The widget can start the timer of its selected habit **without opening the app**. (D10) Therefore the native side owns the timer state, and the app reads it. (Phase 3 note.) |

## 7. Rules after a miss

| ID | Requirement |
|---|---|
| R-M1 | Rules apply to **Build daily** only. |
| R-M2 | One miss (`x`): next day, the habit shows a small "restart" prompt that suggests the timer. |
| R-M3 | Two `x` in a row: the app shows that habit's two reasons side by side and asks "change the time, make it smaller, or keep it?". The answer is not stored. "Change" opens the edit habit screen. The app never changes the habit by itself. |
| R-M4 | Both rules are on by default and can be turned off in settings. |

## 8. Week and weekly review

| ID | Requirement |
|---|---|
| R-W1 | Setting: first day of week. **Default Sunday** (no change for 2.0 users). The calendar grid follows it. Changing it recalculates all weekly numbers. (D9) |
| R-W2 | Weekly review: one card on the review day. Default = last day of the week (Saturday). The card stays on the home screen until dismissed. No notification. |
| R-W3 | Review content: Build habits against goal, Reduce against budget, Number average, and the week's reasons **as raw text, grouped by habit**. No word count. No AI. (D8) |

## 9. Widget

| ID | Requirement |
|---|---|
| R-G1 | Two widgets. **Widget 1, calendar grid**: the 2.0 widget, kept, with 3.1 rules (grey miss, total on the badge, "Today x / N" in place of Done / Missed). |
| R-G2 | **Widget 2, action**: one selected habit. Shows total and this week; follows the kind (Reduce: urges resisted and budget used; Build weekly: "2 / 3 this week"). Has the start-timer tap (see R-T6). |
