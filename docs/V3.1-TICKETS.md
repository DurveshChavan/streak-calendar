# Streak Calendar 3.1 — Phase 4 tickets

Source: `docs/V3.1-ARCHITECTURE.md` (shapes, signatures), `docs/V3.1-REQUIREMENTS.md` (R-ids), `GLOSSARY.md` (words), `docs/adr/`.
Rule from the plan: one ticket per chat, each with tests. Each ticket leaves `npm test` and `npm run build` green.
Work lands on the beta flavor first. Nothing reaches the 2.0 app until the 3.1.0 release.


---

### T0 — Beta flavor and version
- **Do:** `prod` and `beta` product flavors; beta `applicationIdSuffix ".beta"`, name "Streak Calendar Beta". Version 3.1.0 / 30100. npm scripts `android:beta`.
- **R:** R-S3, R-S4.
- **Done when:** both APKs install side by side on one phone; beta starts with empty data.

### T1 — Extract the domain module (no behaviour change)
- **Do:** create `src/domain/`; move `calendar.ts`, the streak rule, `flatten`/`rebuild`/`loadDoc` (as `normalize`) out of `store.ts`. `store.ts` keeps sync only.
- **Done when:** existing tests pass unchanged; a 2.0 `streakcal.v2` doc round-trips byte-identical through `normalize` → `flatten` → `rebuild`.

### T2 — 3.1 data model, records, sync protocol 3
- **Do:** `types.ts` (Shape B); new record prefixes; `normalize` defaults (`kind: 'daily'`, `settings`, `avoid: []`); `actions.ts` skeleton; backup v3 (reads v1/v2). Server: widen `KEY_RE`, `protocol: 3` in `/api/health`, `426` for requests without `v`. Client: send `v: 3`, check health before first push.
- **R:** R-K1, R-K7, section 10; ADR 0002.
- **Tests:** a 2.0 doc loads as Build daily with no change; v3 keys sync; request without `v` gets 426; client on a protocol-2 server stays off with "server needs update"; zero count = deleted record.

### T3 — Week start setting
- **Do:** `week.ts` (`weekOf`, `weekDays`, `lastWeeks`); `set:weekStart` (default Sunday); calendar grid header and rows follow it.
- **R:** R-W1; ADR 0003.
- **Tests:** every week start 0–6 across a month boundary and a year boundary; changing it changes weekly numbers, stores nothing per week.

### T4 — Progress engine
- **Do:** `progress.ts` `total`, `thisWeek`, `trend`, `streak` for all four kinds; `score.ts` `dailyScore`. Write `tests/fixtures/rules/*.json` used later by JUnit (T16).
- **R:** R-P1–R-P5, R-D1, R-D4; E11, E12.
- **Tests:** only `x` breaks a day streak; blank never does; current week does not break a week streak; Later habits excluded; Number has no streak.

### T5 — Home: badge, score, grey miss
- **Do:** badge with total big and streak small; "Today x / N"; missed cell grey, no red on any miss or negative state; long names truncate (canvas fix).
- **R:** R-P1, R-D4, R-C1, R-C2.
- **Done when:** screenshots match the phase 2 canvas Home in light and dark.

### T6 — Day sheet and reasons
- **Do:** per-habit rows by kind; reason field only when a Build habit is `x`; `setReason`; reason kept hidden when the mark leaves `x`.
- **R:** R-D2, R-D3; E2.

### T7 — Build weekly kind
- **Do:** kind in HabitEdit with goal; "2 / 3 this week"; week streak. Daily ↔ Weekly switch allowed.
- **R:** R-K3, R-P3, R-P5; E1.

### T8 — Reduce kind ("Break a habit")
- **Do:** urges +/−, optional budget, slips only with a budget ("x of N used"), replacement action field.
- **R:** R-K4, R-P2, R-P3; E10.

### T9 — Number kind
- **Do:** one value per day, optional unit and weekly target, sum as total, no streak.
- **R:** R-K5.

### T10 — Habits sheet: Later and Avoid list
- **Do:** Later section (pause / resume, data kept); Avoid section (name + replacement, nothing logged).
- **R:** R-K6, R-K8.

### T11 — Habit detail screen
- **Do:** total, this week, streak, 8-week trend bars, start timer, move to Later.
- **R:** R-P4.

### T12 — Miss rules
- **Do:** restart prompt (E7); two-miss sheet after the second consecutive `x` (E6), answer not stored, Change/Smaller open HabitEdit; settings toggle, on by default.
- **R:** R-M1–R-M4.
- **Tests:** blank between two `x` = no two-miss; weekly/reduce never trigger; toggle off hides both.

### T13 — Weekly review card
- **Do:** card on the last day of the week; rows per habit; reasons raw, grouped by habit; dismiss per device (E8).
- **R:** R-W2, R-W3.

### T14 — Timer domain and web port
- **Do:** `timer.ts` `settle`; `TimerPort` with `WebTimerPort` (localStorage); TimerScreen from `endsAt`; drain on start and on visible; one timer at a time with cancel prompt.
- **R:** R-T1–R-T3, R-T5; E3–E5; ADR 0001.
- **Tests:** stop early counts nothing; ends after midnight → start day; settle twice = once; deleted habit → dropped.

### T15 — Native timer
- **Do:** `TimerStore`, `TimerBridgePlugin`, `TimerNotifier` (countdown chronometer + Stop), `TimerAlarmReceiver` (inexact), `POST_NOTIFICATIONS` request, hint when denied.
- **R:** R-T4, R-T5, R-T6; ADR 0001.
- **Tests:** JUnit on `TimerStore` (start, busy, cancel, finishDue, drain). Device check deferred to phase 5.

### T16 — Grid widget on 3.1 rules
- **Do:** payload v3; `WidgetData` kind-aware totals, daily score, week start, grey miss; JUnit runs the T4 fixtures.
- **R:** R-G1.

### T17 — Action widget
- **Do:** `ActionWidgetProvider`, habit picker reuse, Start/Delay → `TimerActionReceiver`, `TimerConflictActivity`, finished-timer overlay.
- **R:** R-G2, R-T6.
- **Done when:** a timer started from the widget with the app closed counts on next open and shows on the widget before that.

### T18 — Glass Bento skin
- **Do:** `skin.css` tokens from the phase 2 canvas: Roboto, one `--done` green in both modes, miss grey, soft glows, frosted tiles; every screen in dark mode.
- **R:** plan section 6; R-C3.

### T19 — Audit fixes A1–A6
- **Do:** as listed in `V3.1-PLAN.md` section 8, plus the published certificate fingerprint. One commit per fix.

### T20 — Speed and size check
- **Do:** measure against `V3.1-PLAN.md` section 9 on the beta build; fix or record each miss.
